## Worker

真实失败发生在 MySQL / Redis 启动检查之后：API `.env` 中存在部署加密密钥，部署消费者因此启动，但缺少制品目录，抛出 `deploy_artifact_dir_required`。旧入口丢弃异常，只打印数据库 / Redis 的通用检查提示。

现在基础设施错误日志保留脱敏消息、堆栈和嵌套 cause。仅开发入口允许在制品目录缺省时跳过部署消费者，并明确输出 `deploy_worker_disabled`；不填默认目录，不更改密钥，不禁用其他消费者。生产入口仍严格要求显式配置，开发入口中非空但无效的目录也仍报错。

本地使用原有 MySQL / Redis，从 `apps/worker` 执行 `pnpm exec tsx src/dev.ts`（验证时设置 `WORKER_HEARTBEAT_MS=2000`），收到 `worker_ready`，持续运行超过 30 秒，多次记录 `worker_heartbeat`、`status: ok`。每次心跳实际调用数据库 ping、Redis 队列计数及数据库补偿查询，不以进程存活代替服务连通性验证。没有触发构建或部署任务。

## 微信、支付宝、Android

Playwright 使用已有 OIDC 演示用户，在 1440×900 视口访问 `b22-uniapp-211600` 的三个页面，记录全部 `/api/` 请求和响应（方法、路径、状态、脱敏响应摘要）。三个配置 GET 的真实结果均为 **200 + 空响应体**：服务返回 `null` 后，NestJS / Express 输出空 body。直接调用 `response.json()` 抛出 JSON 解析异常，引发页面内“操作失败”横幅。项目、成员、构建及任务列表都成功，不是权限或列表错误。

仅可选配置读取启用成功空响应归一化，同时保留 JSON `null`、`configured: false`、配置 GET 404 的设置状态。普通请求不启用该行为；权限失败、网络失败、5xx 和非空畸形数据继续报错。
