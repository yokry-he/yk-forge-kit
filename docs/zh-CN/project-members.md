# 项目成员与角色管理

状态：已实现 OIDC 模式下项目成员列表及现有成员角色调整。尚未实现邀请或邮件发送；没有真实 MySQL 8.0 端到端验证。

## API

- `GET /api/v1/projects/:slug/members`：需要当前用户属于项目，并具备 `member:read`；返回成员 ID、展示名、角色和加入时间，以及当前用户自己的角色。
- `PATCH /api/v1/projects/:slug/members/:userId`：仅 Owner 能调整**现有** Editor/Viewer 的角色，请求 `{ "role": "editor" }` 或 `{ "role": "viewer" }`。

成员列表不会暴露 OIDC 令牌、issuer/subject 或其他身份凭证。对非成员的项目访问仍按服务端范围授权处理。

## 安全限制

- Owner 不得修改自身角色；也不能通过当前接口降低其他 Owner 权限，避免破坏最后一个 Owner 的保护。
- 角色修改在 MySQL 事务中执行，先锁定目标成员行，再更新角色并写入不可直接编辑的 `project_member_audit` 记录。如果任一步失败，事务回滚。
- 原角色与目标角色相同时不产生多余的审计事件。
- `local` 开发模式允许读取已有成员记录，但**禁止修改成员权限**；只有经过验证的 OIDC 身份可发起角色修改。
- 当前不存在直接添加成员的 API，不能绕过身份验证随意制造成员记录；邀请和加入流程要与真实 OIDC 登录衔接后实现。

## 数据迁移

新增 `0004` 迁移创建 `project_member_audit` 表及项目/时间索引。与前面的迁移一样，必须先备份并在用户授权后才可执行，不会在 API 启动时自动迁移。

## 前端

项目详情页面展示成员、角色及当前用户标识。仅 Owner 能看到其他 Editor/Viewer 的角色选择器；更新失败将显示错误，并可手动刷新。成员邀请为后续开发事项。
