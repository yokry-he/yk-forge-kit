# 可视化资产中心（MVP）

当前页面地址：`/assets`，通过 Vue Router 与 `/projects/new` 项目创建向导分开维护。

## 交互原则

1. **先发现，再决策**：搜索资产名称、ID、能力；筛选兼容平台。
2. **先了解依赖，再安装**：详情展示版本、适用目标、提供的能力和依赖资产。
3. **先预览，再操作**：展示示例文件变更，并提供真实项目的 CLI `asset plan` 命令。
4. **真实反馈**：按钮仅复制 CLI 命令，不将其描述为已经安装；没有云端项目工作区时不提供假的安装进度。
5. **明确未实现范围**：业务资产（用户中心、权限管理、大屏等）以规划状态展示，不进入可安装目录。

## 已实现

- Vue Router 页面分离与工作区导航。
- 基于 `@forgekit/asset-core` Registry 的资产搜索、平台过滤及详情。
- 示例安装变更预览（非真实项目的文件状态）。
- 本地 CLI 的预览与安装命令复制，项目路径使用 POSIX Shell 引号转义。
- 搜索无结果、API 不在线等场景的明确反馈。

## 限制和后续

- 当前只有一个官方内置示范主题资产；搜索与过滤框架为后续多资产准备。
- 页面没有用户认证、云端项目文件读取或已安装资产清单。真实项目的兼容与冲突以 CLI `asset plan` 检查结果为准。
- 当前页面提供升级与卸载的 CLI 预览命令，确认后才在终端添加 `--yes` 执行。
- 未来增加项目关联、版本历史和针对真实项目的差异化预览；需要在安全的执行后端和用户授权机制完成后才允许浏览器触发真实文件变更。
- 生产 SPA 托管需将 `/assets` 等客户端路由回退到 `index.html`。
