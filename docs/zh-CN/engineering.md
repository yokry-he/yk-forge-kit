# 工程开发规范

状态：初版 / 2026-11-15。约束等级见根目录 `AGENTS.md`。

## 技术选择

- 默认 Web 前端：Vue 3、TypeScript；优先 Composition API 和 `<script setup>`。
- 在产品需求明确后评估 Vue 应用框架（如 Nuxt）与构建方案（如 Vite）；通过 ADR 记录选择，不因流行度直接定案。
- 依赖以成熟、维护良好、生态健康为前提；记录用途、替换成本与许可。版本锁定并以自动化验证驱动升级。
- 不预设必须微服务化。优先模块化单体，待部署、扩展或组织边界真正需要时拆分。

## 模块与依赖

- 按业务能力组织目录；UI、应用编排、领域逻辑、基础设施的依赖方向应清晰。
- 禁止循环依赖、跨模块读取内部状态、共享可变单例。
- 外部 AI 提供商、云厂商、存储和支付通过接口与适配器隔离。
- 抽取前评估：语义是否一致、接口是否稳定、是否真正复用、引入的依赖成本、性能和测试收益。
- 合理重复优于错误抽象。禁止只凭“出现两次/三次”机械提取。

## 公共 UI 组件

- 公共、业务无关、API 稳定的组件进入独立的 `yk-forge-ui` 仓库。
- 业务流程组件（项目向导、部署配置、资产安装）留在 YKForgeKit 内。
- UI 库共享 Design Tokens、可访问性规范及适当的无头逻辑；不同渲染目标允许独立实现。
- UI 包须有版本规则、使用示例、交互与无障碍测试、变更日志及兼容政策；不允许反向依赖 YKForgeKit 业务模块。
- `yk-forge-ui` 尚未创建；创建前先通过 ADR 确定包边界与发布策略。

## API、数据与安全

- API 采用一致的身份认证、参数校验、错误结构、分页与版本策略。
- 数据库结构以迁移脚本变更；上线迁移需评估回滚或前向修复策略。
- 秘钥与凭证不得写入源码或日志，最小权限发放，生产部署应具有人工授权边界。
- 任意用户构建脚本执行于隔离 Runner，设置资源、时间、文件系统和网络策略。

## Git 与交付

- 每项变更走功能分支 → PR → CI → 审查 → 合并的路径。
- PR 内容包含：需求/问题、实现说明、测试结果、影响与回滚办法。
- 合并前至少进行格式、Lint、类型检查、相关测试与构建验证；实际检查名称待 CI 初始化后锁定。
- 重大架构决策新增 ADR；不因局部修改顺带重写无关模块。
