# 测试与质量门禁

状态：初版，具体工具与命令将在工程初始化 ADR 中确定。

## 测试分层

- 单元测试：纯逻辑、依赖解析、配置解析、业务规则与错误分支。
- 集成测试：API/数据库、资产安装、适配器契约、构建任务编排。
- E2E：项目创建 → 安装资产 → 构建 → 预览/部署等关键用户路径。
- 组件测试：交互状态、键盘操作、焦点管理、无障碍语义、主题切换。
- 安全测试：权限边界、凭证处理、恶意输入与构建隔离。
- 回归测试：修复缺陷时优先补充失败场景。

## PR 最低门槛

1. 必须通过格式、Lint、TypeScript 检查。
2. 必须通过受影响模块的自动化测试与构建。
3. 影响公共 API、资产协议或数据库时，必须提供兼容性验证与迁移说明。
4. 影响 UI 时，应该检查主要断点、深浅主题、键盘可用性及关键交互。
5. 不允许以跳过检查作为长期解决方案；短期例外需写明责任人和补救计划。

## 执行原则

测试覆盖率可用于发现风险，但不以单一覆盖率数字代替质量判断。优先保护高风险领域和核心用户链路。构建、部署、发布要区分任务成功与最终上线成功。
