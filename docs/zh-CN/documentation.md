# 文档语言与维护规范

## 当前策略

设计与快速迭代阶段先完成准确的简体中文文档，`docs/zh-CN/` 是权威来源；英文将在架构和术语稳定后分批翻译。这是有意的阶段性安排，不代表放弃双语目标。

## 目标目录

- `docs/zh-CN/`：简体中文原文。
- `docs/en/`：英文译文，逐步补齐并保持同名相对路径。
- `docs/adr/`：架构决策记录，当前可使用中文并附英文标题/摘要，后续统一整理。

## 翻译工作流

1. 文档 PR 更新中文原文。
2. 如对应英文已存在，同一 PR 应同步更新；暂时不能同步时显式标注翻译待更新并跟踪任务。
3. 核心用户指南和发布文档在公开正式发布前必须有中英文版本。
4. 术语统一：资产（Asset）、能力（Capability）、适配器（Adapter）、构建执行器（Runner）、项目清单（Manifest）。
5. 英文译文必须经人工或可靠审查确认技术语义；避免过期或不准确的翻译。

不要将缺失译文伪装成已完成。后续可以增加文档链接检查、对应文件检测及翻译状态 CI。
