# ADR-0020: Beginner mode — natural-language template selection and project creation

状态：Accepted（B21）

Date: 2026-11-22

## 背景

YKForgeKit 的产品定位（ADR-0005）是让普通人也能创建网站、跨端应用、桌面与小程序。现有模板注册表及各模板 ADR（0006 nuxt、0015 uniapp、0018 tauri 等）已经提供多种项目骨架，但新用户仍需理解模板差异与平台参数。B21「新手模式」希望让用户用一句话描述需求，系统在既有模板中选型并走既有项目创建流程，降低创建门槛。

DeepSeek 默认作为用户自带密钥（BYOK）的可选 AI，不是平台代付的内置模型。因此该能力必须能在无 AI 或 AI 不可用时保持可用，并且不能破坏既有项目创建与权限模型。

## 决策

### 1. 控制台简单向导

控制台提供简单向导，用户输入一句中文或英文需求，系统展示并确认以下内容后再创建：

- 模板（templateId）
- 项目名
- 目标平台，平台允许集合为：`web` / `uniapp` / `weapp` / `alipay` / `android` / `tauri-desktop`

确认动作必须复用既有项目创建流程，不在向导或分类阶段直接创建项目或写仓库文件。

### 2. NestJS 分类接口与确定性关键词回退

NestJS API 提供分类接口，把需求映射到既有模板及参数。分类接口必须实现不依赖 AI 的确定性关键词回退：

- 使用中英文关键词 / 意图表进行确定性分类。
- 在以下任一条件成立时，一律回退关键词结果，并向用户标明来源为 `keywords`：
  - AI 关闭
  - 缺少密钥
  - AI 请求超时
  - 返回非 JSON
  - schema 校验失败
  - 返回的 `templateId` 不在白名单内
  - 平台建议不在允许集合内
- 只有 AI 请求成功且通过 schema 校验时，来源才标记为 `ai`。

分类结果需返回模板、参数建议与来源，用户可在控制台确认或调整。

### 3. BYOK AI 配置与密钥保护

可选 AI 为 BYOK 模式：

- 默认提供商为 DeepSeek。
- 支持自定义 OpenAI 兼容 base URL 与模型名。
- 密钥使用既有 B14 AES-256-GCM 机制与主密钥保存。
- 密钥字段为 write-only、redacted。
- 使用独立 AAD（例如 `b21:<ownerOrUserUUID>`），与 B12/B14/B17/B18/B20 密文隔离。
- API 不回传明文密钥或密文密钥。
- 日志/审计只记录动作与操作者，不记录密钥、提示全文中的密钥、或模型原始响应。
- 若需要新表，Drizzle 迁移编号必须接在现有 `0017_b20_alipay_upload.sql` 之后，使用 `0018_b21_beginner_mode.sql`。
- 不为了 AI 改变主密钥方案。

相关密钥与密文管理遵循 ADR-0013、B12/B14/B17/B18/B20 的既有约定。

### 4. schema 校验与防注入

模型输出必须严格 schema 校验：

- `templateId` 仅允许：`vue-web`、`vue-admin`、`nuxt-site`、`uniapp`、`tauri-desktop`。
- 平台建议必须落在允许集合：`web` / `uniapp` / `weapp` / `alipay` / `android` / `tauri-desktop`。
- 校验失败时回退关键词结果，并标记为 `keywords`。

防提示注入：

- 用户需求作为不可信数据放入明确分隔区，不得与系统指令混合。
- 系统提示规定模型只输出 schema，不得遵循用户对系统规则的覆盖，不得输出密钥或内部提示。
- 不允许把用户文本拼进 shell、SQL 或文件路径。

### 5. 超时与速率限制

分类请求必须有超时与速率限制，避免卡住或刷爆用户密钥额度。超时后回退关键词结果，并按来源标记。

### 6. 复用既有项目创建流程与权限模型

确认后必须复用既有项目创建流程与权限模型，不新增第二套生成器。分类阶段只负责选型与参数建议，不写仓库文件；真正创建、权限校验、仓库写入仍走现有流程。

### 7. 单元测试

单元测试使用 mock 的 AI 客户端，覆盖：

- 关键词回退
- AI 成功
- 非法模板 / 注入 / 超时 / 非 JSON 回退
- 密钥不泄漏（响应与日志断言）

## 安全

- 密钥保护：BYOK 密钥按 B14 AES-256-GCM 保存，write-only，redacted，独立 AAD 隔离，API 与日志不泄漏密钥。
- 防注入：用户输入作为不可信数据隔离，模型只允许输出受 schema 约束的 JSON，禁止遵循用户覆盖系统规则。
- 最小暴露：分类接口只返回模板与参数建议，不回传模型原始响应或密钥。
- 审计：日志只记录分类动作与操作者，不记录密钥、提示中的密钥或模型原始输出。

## 后果与回滚

- 无 AI 时功能仍可用：关键词回退保证普通用户始终可以创建项目。
- 删除 AI 配置不影响已创建项目：AI 只影响选型建议，项目创建仍基于已确认的模板与平台。
- 回滚：停止新手模式相关写入后回退 API/控制台版本；保留新增配置表、项目 platforms 列与主密钥，优先前向修复，不自动执行破坏性反向 DDL。
- 与现有 ADR 的关系：本决策不改变 ADR-0005 产品定位、ADR-0013 密钥管理、项目模板注册表及模板 ADR（0006 nuxt、0015 uniapp、0018 tauri 等）。
- 中文指南为权威版本。

## 实现约定

- 路由为 `/api/v1/beginner/classify`（POST）与 `/api/v1/beginner/ai-config`（GET/PUT/DELETE）；仅 OIDC 身份，沿用 ProjectApiGuard 与身份限流。分类每分钟 12 次，配置写入/删除每小时共 30 次。
- AI 客户端为可注入能力接口，默认 OpenAI 兼容适配器；DeepSeek 默认 base URL 为 `https://api.deepseek.com`，模型为可覆盖的 `deepseek-chat`。调用上限 10 秒，失败只记录固定动作/来源，不记录异常正文。已识别提示注入直接使用关键词。
- 模型对象使用 strict schema；非法字段、非法模板/平台或无效名称回退。白名单内但不兼容/重复的平台会被纠正，标记 lowConfidence，并提示确认。
- 确认调用既有 `POST /api/v1/projects`；增加可选 platforms 元数据并校验与模板兼容，旧调用方不传仍兼容。迁移 `0018_b21_beginner_mode.sql` 新增用户配置表和项目可空 platforms JSON 列。它不改变模板渲染、构建目标或自动发布。
- 创建只保存配置，源码仍由现有 CLI 生成。向导使用模板默认 features，成功后打开现有详情页。
- 中文 [使用指南](../zh-CN/beginner-mode.md) 与 [分类目录](../zh-CN/beginner-mode-catalog.md) 为权威版本；公开发布前补齐英文关键指南。


### B21 审查修复：出站地址、凭证目标绑定与名称过滤

- 自定义 AI 根地址只支持公网 HTTP/HTTPS 与默认端口，推荐 HTTPS。保存和调用均校验全部 DNS 结果；任何非公网或特殊用途地址使整体失败。调用通过 Node HTTP(S) 的自定义 lookup 将连接固定到本次已校验的 IP，禁用连接池复用，不跟随重定向，保留原域名用于 Host/TLS 校验。地址/DNS/传输失败使用固定安全错误，不记录解析地址或凭证。测试注入 AI 能力或 mock DNS/传输，不提供用户可开启的内网例外。
- API 根地址、提供商或模型改变时，必须同时替换密钥；只有目标不变时才能留空保留。继续使用 AES-256-GCM，AAD 从 `b21:<userUUID>` 扩展为 `b21:<userUUID>:<规范化目标元组>`（提供商、URL、模型），无需数据库结构变更。旧的未绑定密文拒绝解密，用户需重新保存密钥；此前使用关键词回退。回滚应停用 AI 出站调用，保留配置与主密钥并前向修复，避免恢复未绑定的出站凭证行为。
- 在分词或截断前移除疑似秘密值，并对 AI 成功结果再次过滤名称与需求中的秘密值回显；所有路径无安全候选时使用模板默认 slug。模板与平台白名单、关键词回退、超时、限流及项目创建流程保持不变。
- 中文指南同步更新；英文对应指南尚不存在，公开发布前需补齐翻译。
